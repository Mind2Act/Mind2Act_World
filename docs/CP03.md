Trees differ only in `cases_unified/CP03/expert.py` (a hard rack-move helper); scene, world,
quality, selector and scoring modules are byte-identical, so one code path serves all difficulties.

force, `a.grip_force`) is the old evaluation layer and is not migrated.

## Red texture / configuration entry
Delivered H5s were recollected with the original YCB029 red plate texture restored (only the
authored scene changed; actions, joints and times are numerically identical). The per-case native
spec `TRAIN/CP03/<diff>/<case>/provenance/red-texture-native-spec.json` carries M, C and setup;
`tasks/CP03/instances.py:instance_document` validates it, drops planner/private fields and emits the
`InstanceSpec` document (`assets.station` = scene layer, `assets.texture_map` = recovered YCB029
texture, `assets.x5` supplied by the caller, `config.robot_rest` = the baseline HOME + 0.044 m).
`verify_assets` checks both files against the closure digests; a missing texture raises, there is no
substitute. Hard-coded developer paths are rejected from the document.

## Kept / changed
Kept: rail motion (Easy/Medium one-way, Hard shuttle with 0.6 s reversals), selector gear pawl and
detents, Start/Send plunger logic, per-plate stable placement (120 ticks, 0.004 m), moving-insertion
predicate, tilt windows (`PlateQuality`), unexpected-robot-contact gate, document stage evidence
(valid Start, gear qualified after 120 released ticks), scoring (rule below)
(superseded, see Scoring below).
Changed: robot work via `ctx.robot` only (the redundant gain block equals the shared profile and is
verified by `ctx.robot.verify`); hooks `before_step/after_step`; no warm-up (source used `warmup=0`).

## Decisions needing review
1. Source `Collector` also gated success on `tracking < 0.05 rad` and `command_continuity < 0.05 rad`.
   They compare measured joints against the expert's recorded command row and cannot be defined for
   an arbitrary consumer (a model's per-tick jumps would fail them). Not migrated; success uses the
   original placement, tilt-window and unexpected-contact gates.
2. Medium/Hard start with the left joint1 parked by -0.3 rad (baseline `build`), applied once before tick 1
   through the shared `ctx.robot.park_arm("Left", deltas)` (offsets the current initialized pose; repeated
   calls accumulate).
3. Station base poses are applied by the shared robot service (`ctx.robot.mount_bases(..., legacy_anchors=True)`
   after `prepare_stage`, before articulations/reset; the service reads the joint back). The task never writes
   the FixedBase joint.
4. Early completion: `is_complete` ends the episode once all three gates hold (placements stable,
   tilt windows passed, no unexpected contact); common input full_success additionally follows from that.

## Scoring: carried source plate + moving-rack placement + terminal slot

Version `cp03-carried-dynamic-terminal-20261104-v4` applies the 2026-11-04
19:00 clarification. Each credited plate must meet all three conditions:

1. It is a task source plate physically picked up and carried by the gripper.
   The existing opposed-finger and source-relative 40 mm lift measurement
   establishes pickup. Receiver preloads and pushed/knocked-in stock do not count.
2. It was placed into the slot after correct gear selection, valid Start and
   actual rack motion, with measured rack speed strictly above the existing
   0.5 mm/s threshold. Medium/Hard retain the source 120 released correct-gear
   ticks before a fresh Start press; Start must be released. Easy has no gear step.
3. At episode end it is released and supported in a unique initially empty slot,
   within the original slot width and 12 mm height error, |normal x| > .985,
   and stable for the last 120 ticks with rack-relative displacement ≤4 mm.

Placement admission records entry into the geometric slot region, independently
of the onset of support. Both held insertion and release above the slot followed
by falling into support qualify. There is no held/support overlap requirement
and no once-per-episode first-support timestamp gate. A plate left in a stationary
slot cannot qualify just by starting the rack later; removing and placing it again
after valid setup can qualify. Entries identify the slot as well as the tick,
speed, control readiness and measured pickup status. Terminal evidence also
includes per-plate geometry/support/release and its trailing stability window.

Transport tilt, unrelated contacts, send/reversal histories remain diagnostic.
Score stays 100 for complete success, otherwise `20*k/N` with the existing final
wrong/extra penalty and N=4/7/9. Gear→Start step order is preserved. Coding
Goal/recipe follows this rule; E2E text is unchanged. Old/unversioned aggregate
evidence cannot be relabeled as the new scoring version.

The published-result rerun screen uses native Start success, not partial score
or terminal poses. All 150 archived attempts were checked: 18 successfully
started (Easy 13 / Medium 3 / Hard 2), including 7 with wrong/extra items (4/2/1).
The other 132 never started and receive no plate credit under either rule. The
original pre-Start wrong-item penalty is preserved so invalid pre-Start placement
cannot restore gear-only partial credit. PRO `diagnostics/cp03-start-rerun-screen`
records the exact selected/excluded source paths, evidence hashes and ledger
replacement; original episode evidence/results and live deployments are unchanged.
