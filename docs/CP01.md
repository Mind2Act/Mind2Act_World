`audit_native` asserts 0.002), `repair_foods`/`repair_fixture_primitives`, collision off ->

The sprint line "CP01 adds no CCD/TGS/offset/repair" was withdrawn: it was based on the
review table citing `mind2act_env/worlds/cp01_scene.py`, which is not the selected baseline.

## Differences from the old eval (`cases/CP/CP01/runtime/scene.py`, to be dropped)
Old-eval-only additions are not migrated: `restore_asset/configure_stage/verify_native`
inside the task (X5 now only via `ctx.robot`), the old `world.py` wrapper
(`worlds_v2.attach`, `final_assets`, Carrier/frozen_cp12 paths), score adapters bound to
`mind2act_benchmark`. Scoring (K0 ruling 2026-11-01, snapshot
`common_input-20261101/CP01.md` sha256 67c5be0b..., section 6): success = 100; otherwise `20*k/N`, N = 3/8/12 (Easy: 3
foods; Medium/Hard: trays separated and flat, then foods in the matching trays), k = satisfied steps minus one per
wrong or extra item left in the final state (minimum 0), tray setup counts only for foods that became stable after
it, via the shared `contracts.score_from_completion`. Completion `{k, n, ratio}` is reported separately in the score
components. The earlier `100*k/n` ratio rule is superseded.

## Runtime wiring (T0 PR5 docs/runtime.md)
- sim opens `spec.assets["station"]`; `ctx.world` is lazy and not reset; this task authors USD
  then calls `world.reset()` at the baseline position (collision off -> reset -> home -> single task
  reset -> collision on).
- `ctx.robot`: `prepare_stage` (restore pinned asset + official X5 configuration), `attach_cameras`,
  `articulations`, `rest_pose`/`reset_to_rest` (the only joint writes), `verify`. The instance must set
  `assets.x5` (relative ARX.usd) and `config.robot_rest` (8 values from this baseline's home pose).
- `ctx.sim.contacts`: `touch`, `bilateral`, `held_tilt`; build subscribes before the 120-tick warm-up
  (held rest, belt speed zero) and calls `clear()` afterwards, like the baseline's `attach(warmup=120)`.
- Hooks: `before_step(tick)` drives belt/reference orders for time `(tick-1)/120`; `after_step(tick)` measures,
  switches observation->execution phase and updates the tracker; `evidence(tick)` only reads it.
- 120 Hz only: build rejects another `physics_hz`. Observation carries `spec.protocol_version`.
- Instance config layout kept from source: `config.native_inputs.setup`, `config.max_food_tilt_deg`.
- `reset_to_rest` additionally zeroes the velocity target in `apply_action`; the baseline loop left it implicit.
- The fries mass-properties JSON no longer carries the developer-local evidence path.

## Tray scoring correction
All trays, including the former designated last tray, are graded by their terminal
state: separate tabletop footprints, flat, table-supported and released, with the
existing 120-sample / 3 mm stability check. Tray movement, grasp/lift history and
configured target coordinates are not success requirements. Footprint separation
uses current tray rotations; food containment and order matching use current tray
poses. Initial overlap, movement or grasping does not permanently invalidate a tray.
Food transport checks and the scoring formula remain unchanged, including exactly
20 points for an unsuccessful run with all required steps satisfied and no extras.

The prompt/scorer audit's CP01-03 records expert Medium episode 2 / attempt 2 moving
the last tray by 0.100065 m and Hard episode 1 / attempt 5 by 0.101908 m. Those known
traces conflict with the removed stationary-last-tray gate; the raw H5 files were
not independently replayed for this correction. Training H5, E2E English, source
bindings and historical outputs are unchanged.
