## Scoring (K0 ruling 2026-11-01; snapshot `common_input-20261101/CP02.md` sha256 5e340246..., section 6)
Success = 100. Otherwise `20*k/N` (< 20): N = 4 / 8 / 10 (Easy 4 macarons; Medium lid >90 deg, valid Start, 6
macarons; Hard adds Stop with the turntable settled and the cover seated and released). k = satisfied steps in the
final state minus one per wrong or extra item left (macaron or cover resting on the cake, released, but not at its
target), minimum 0; lid / Start count only if done before the first macaron, Stop before the cover; Easy's automatic
start and demonstration are not steps. Scored through the shared `contracts.score_from_completion`; `completion` is `{k, n, ratio}` and adds no score. The earlier 90/70/60-weight rule is superseded. The source required a completed
terminal reason for success; the runner ends the episode as COMPLETED exactly on native success.

read-back); the task never writes the FixedBase joint.

## Native reset deadline

The single `world.reset()` call is bounded at 300 wall-clock seconds. This is
an infrastructure initialization limit, separate from the model's episode and
physics budgets. A fresh worker records `native-phase.json` and arms the C-level
`faulthandler` watchdog into `native-phase-traceback.log`. A timeout dumps all
Python threads and exits that worker even if native code holds the GIL. Normal
return or an exception cancels the watchdog before later work/cleanup and records
`completed` or `failed` in the phase receipt.

The supervisor recognizes a timeout only when the running receipt belongs to
its exited child and the trace starts with the watchdog's `Timeout (` record.
It retains both artifacts and reports an invalid `wall_timeout` with null score,
not a model failure or a zero. Other worker failures retain their existing
classification. This uses the ordinary owned-worker lifecycle and does not
change scene geometry, solver settings, task rules or retry policy.

Read-only evidence for `CP02_medium_13db98f8d03429e7`, PRO C GPU 0 wave 24:
`CP02_RESET_BEGIN` appears but `CP02_RESET_DONE` does not; the worker was stopped
after 4,521.09 seconds with no reset stack. Its whole-worker wall budget was
12,584 seconds, so it did not bound this initialization stall usefully. The
PhysX material/solver warnings are not enough to establish the native root cause.
This change bounds that failure and captures the next stack; it does not claim
to fix the underlying PhysX stall. No GPU reproduction or deployment change ran.

CPU guard regression: `python -m pytest tests/test_native_phase_deadline.py -q`.
It uses a fake `World.reset` with a GIL-holding `ctypes.PyDLL` call in a fresh
child, and checks timeout classification, null score, trace retention,
cancellation after return/error and rejection of foreign/corrupt receipts.
